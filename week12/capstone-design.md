# 一页Capstone设计卡

| 项目 | 本项目选择 |
| --- | --- |
| 问题 | CPU条件下，将混合类型中文PDF解析为Markdown/JSON时，是否应该保留OCR？内容相似度能否反映结构可用性？ |
| 用户与价值 | 学习者/研究同学，需要可追溯的文档解析实验和明确的失败边界 |
| 路径 | 标准：完整研究卡、证据、离线复现、展示及自评；扩展选择可复现实验包 |
| 输入 | Week07自制CC0中文PDF v1，冻结test共24页：数字/扫描/表格各8页，参考与PDF分存 |
| baseline | Week07 Docling CPU+RapidOCR默认配置，原始历史输出，经Week10与本周重新认证 |
| 唯一核心变量 | `do_ocr: true → false`；身份标签和输出目录不参与算法，其他解析选项相同 |
| 方法 | 不改模型；复用Week10真实关闭OCR运行，在同一24页和原Week07指标上配对比较 |
| 判断方式 | 主指标为页级归一化字符编辑相似度的宏平均；同时看扫描切片、阅读顺序、表格网格/合并单元格严格匹配、失败与成本 |
| 当前采用标准 | 混合文档默认项必须保留扫描页可读内容；关闭OCR造成扫描切片退化则不采用为全类型默认。表格strict失败禁止以内容分高宣称结构正确 |
| 停止条件 | 输入/源码/输出SHA不符、独立核验失败、缺页或派生数值不同则停止，保留错误；不为提分修改预测，不调整已消费测试集上的超参 |
| 资源上限 | 本周归档重算每个独立核验120秒，CPU、无新增付费云费用、无新训练；包内不放完整基础模型 |
| 主要交付 | 唯一入口、配置、Project Card、原始结果证据索引、成本/错误/决定、五分钟演示、答辩、自查、四周计划 |
| 成功边界 | 当前VM及隔离clone可重算；同学独立复现与本人自主答辩完成后才能勾选对应最终检查 |

这是对已有实验的回顾式设计整合，制定时已知Week10结果，不是新实验的预注册。LoRA rank4/8与A/B学习率是旁支历史证据，不加入本卡的“唯一变量”。端到端PDF→LoRA字段抽取、真实业务泛化、公共benchmark排名和生产部署均不在本次范围内。
