# 能运行、可复现与可审计的区别

在软件开发和人工智能研究中，“程序能运行”只是最低要求。一个研究项目如果希望由其他人验证、复用和进一步改进，还需要达到可复现和可审计的要求。三者并不是相互独立的概念，而是由低到高逐步增强的研究工程能力。

## 1. 能运行

“能运行”是指程序可以在开发者当前的计算机和已有环境中成功执行，并产生预期结果。它主要回答的问题是：“这个程序现在是否可以运行？”

例如，本项目执行以下命令后，能够输出测试图片的宽度、高度和格式：

```bash
python src/image_info.py samples/demo.png
```

程序输出图片宽度为 640、高度为 480、格式为 PNG，说明工具已经具备基本功能。但是，仅凭这一结果不能证明项目可以在另一台计算机上运行。开发者的电脑中可能已经存在未记录的 Python 包、环境变量、缓存文件或系统配置，这些隐藏状态可能是程序成功运行的真正原因。

因此，“能运行”的主要证据是当前环境中的一次成功执行，但其局限在于依赖开发者已有的本地环境。

## 2. 可复现

“可复现”是指其他人在没有开发者口头说明的情况下，能够根据仓库中的文档、代码、依赖和输入，在一个干净环境中重新运行项目，并获得一致或可接受范围内一致的结果。它主要回答的问题是：“其他人能否重新建立实验过程并得到相同结论？”

一个可复现项目通常需要提供：

* 明确的 Python 和关键依赖版本；
* 可以重新创建的独立环境；
* 可复制的安装和运行命令；
* 来源明确或可重新生成的输入数据；
* 自动化测试及预期结果；
* 成功输出、错误输出和已知限制；
* 不依赖开发者个人目录的相对路径。

本项目通过 `requirements.txt` 声明 Pillow 和 pytest 的版本，通过 README 提供环境创建、依赖安装、程序运行和测试命令，并使用 `scripts/create_sample.py` 生成固定尺寸的测试图片。随后在全新 clone 和全新 venv 中重新安装依赖，得到相同的图片尺寸和 `3 passed` 测试结果，说明项目已经达到基本的可复现要求。

对于后续包含随机采样、GPU 计算和深度学习模型的实验，可复现不一定意味着所有数值逐位完全相同，还需要记录随机种子、模型 revision、数据版本、硬件信息和允许的误差范围。

## 3. 可审计

“可审计”是在可复现基础上进一步要求实验过程和结论能够被追踪、检查和解释。它主要回答的问题是：“别人能否判断结果是如何产生的，以及每项修改为什么发生？”

可审计项目不仅要保存最终代码，还要保存：

* 输入数据的来源和授权情况；
* 代码、配置和依赖版本；
* 每次修改对应的 commit；
* 修改的目的和验证方法；
* 原始运行结果和失败案例；
* Pull Request 与 Review 记录；
* 已知限制、未解决问题和人工判断；
* AI 工具参与范围及人工验证记录。

在本项目中，Git commit 保存了工具实现、测试、文档修复和复现记录等修改历史；Pull Request 展示了开发分支与 `main` 之间的差异；`evidence/` 保存了环境、成功运行、测试和错误处理的原始输出；`docs/project_plan.md` 说明了项目范围和非目标；`docs/reproducibility_notes.md` 记录了全新环境复现过程。这些证据使他人不仅能重新运行项目，还能检查项目如何逐步形成。

## 4. 三者的关系

| 层次  | 核心问题           | 主要证据                 | 典型不足          |
| --- | -------------- | -------------------- | ------------- |
| 能运行 | 当前电脑能否执行？      | 一次成功运行结果             | 依赖本地隐藏状态      |
| 可复现 | 他人能否重新得到结果？    | 环境、依赖、输入、命令和测试       | 可能缺少修改理由和完整历史 |
| 可审计 | 过程和结论能否被追踪与检查？ | Git 历史、PR、原始输出、来源和限制 | 需要持续维护证据链     |

三者可以理解为逐层包含的关系：可审计项目首先应当可复现，可复现项目首先应当能够运行；但能够运行的项目不一定可复现，可复现的项目也不一定已经具备完整的审计证据。

## 5. 本周认识

通过 Week 1 的实践，我认识到科研代码的价值不仅在于得到一次正确输出，还在于能否让其他人理解、重新运行和验证结果。README、依赖文件、测试、Git 历史、失败输出和复现记录并不是附属材料，而是研究结果的一部分。后续开展模型推理、文档解析和微调实验时，应继续记录模型 revision、数据来源、配置、原始输出和失败案例，使实验从“在我的电脑上能运行”逐步提升为“他人能够复现并审查”。
