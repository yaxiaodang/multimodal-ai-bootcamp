| 任务 | 输入 | 方法 | 输出 | 指标/人工判定规则 | 常见错误（概念示例，非本次发现） |
| --- | --- | --- | --- | --- | --- |
| OCR（文字识别） | 含文字的页面图像 | 定位并识别文字；本次工具待定 | 识别出的文字，可附位置 | 对照人工参考文字，逐项记录错字、漏字、多字 | 文字内容错误；文字全部出现也不能证明表格结构正确 |
| Layout analysis（版面分析） | 文档页面 | 区分标题、正文、表格等区域；本次工具待定 | 区域位置及类型；阅读顺序可另行恢复 | 对照人工区域与类型；顺序单独检查，不与文字正确性混算 | 标题区域误判；双栏交替拼接是阅读顺序错误，可在后续解析中暴露 |

| Document parsing（文档解析） | 文档页面或完整文档 | 整合文字、区域、层级、表格、公式和阅读顺序；本次工具待定 | 结构化文档表示，如 Markdown / JSON | 分项核对标题层级、正文归属、表格、公式及阅读顺序 | 提取到“第一章 实验方法”，却没有表达它是标题及其层级 |
| Document VQA（文档视觉问答） | 文档页面与问题 | 根据相关内容回答问题；本次工具待定 | 答案；工具支持时可提供证据或解释 | 答案正确性与所给证据/解释是否符合原文分别记录 | 实付金额答对 110元，却声称商品金额为 110元，解释与文档冲突 |

## 本人已表达的理解

- 数字 PDF 中的文字与扫描页图像需要采用不同的文字获取方式；图像文字需要 OCR。扫描 PDF 已有 OCR 文字层的情况已在说明中提示，尚未用实际文件核验。
- 产品价格示例共有 3 行 2 列；纯文本缺少表格结构信息。
- 双栏交替拼接属于阅读顺序错误，即使文字识别正确也会影响段落连贯性。
- 标题与正文应有不同角色，并保留标题层级。
- 公式需要保留字符之间的位置和结构关系。
- 订单示例应分别记录：最终答案 110元正确；“商品金额是110元”的解释错误，不符合原文。

以上是对教学例子的辨析，不能作为真实文档实验的成功或失败案例。生成的解释与文档冲突，是可观察的输出问题；不能据此确定模型内部如何得到答案。

## 本轮工具与评价范围

已准备的基线：Poppler 22.02.0 的 pdftotext，对三份 PDF 第 1 页提取 UTF-8 纯文本，采用默认读取策略，不执行 OCR 或模型推理。

Codex 给出的工具定位：这是 PDF 文字提取基线，可检查文字保留与顺序，并观察结构信息的缺失；它不输出显式标题标签、合并单元格表示或公式 LaTeX，也不回答文档问题。不能把它当成 OCR 模型、结构解析系统或 VQA 模型的能力评测。
